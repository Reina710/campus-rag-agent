# LLM-as-judge（模型当裁判）

## 一句话

**用另一个模型给回答打分，补上"关键词匹配"测不出的：答非所问、编造、漏限定。**

## 为什么需要

`evaluate.py` 的"回答通过率"是靠关键词（`keys`）匹配的：回答里出现 `40` 就算过。

但它测不出三件事：

| 问题 | 例子 |
|---|---|
| 答非所问 | 问"一等多少钱"，回答里碰巧有"12000"但答的是别的 |
| 编造 | 资料里没写，模型自己补了一个数字 |
| 漏限定 | 资料写"最长 2 年"，回答只说"2 年" |

所以再加一个模型当裁判，按两个维度打分：

| 维度 | 含义 | 5 分 | 1 分 |
|---|---|---|---|
| **faithfulness**（忠实度） | 回答是否只依据资料 | 每个结论都能在资料里找到 | 明显编造 |
| **relevance**（相关性） | 是否真的回答了问题 | 直接、完整 | 答非所问 |

## 怎么跑

```bash
# 先跑 5 题试水（每题 2 次模型调用：答 1 次 + 判 1 次）
python src/eval_judge.py --limit 5

# 只跑独立评测集
python src/eval_judge.py --split holdout

# 全量（199 题，约 400 次调用，比较慢）
python src/eval_judge.py
```

输出示例：

```

[ 1/3] 专硕的基本修业年限是多久？   忠实=5 相关=5
[ 2/3] 专硕最低要修满多少学分？     忠实=5 相关=5
[ 3/3] 专业实践要完成几个月？       忠实=5 相关=5
平均忠实度：5.00 / 5
```

报告写到 `reports/judge_<split>_<时间>.txt`。

## 代码在哪

| 文件 | 作用 |
|---|---|
| `src/eval_judge.py` | 全部：检索 → 生成 → 裁判打分 → 汇总落盘 |

## 设计取舍（面试可以讲）

1. **用 rag 模式，不用 Agent 循环**：裁判要评"答案质量"，不希望被工具调用的随机性干扰。
2. **裁判和答题用同一个模型，但温度 0、提示词独立**：尽量降低"自己夸自己"的倾向。
3. **每题两次调用**，全量约 400 次，所以默认只跑 20 题。

## 和关键词评测的关系

**不是替代，是补充。**

| 评测方式 | 测什么 | 成本 |
|---|---|---|
| 关键词匹配（`evaluate.py`） | 有没有出现关键数字/词 | 便宜、快，但粗 |
| LLM-as-judge（本脚本） | 有没有编造、答得对不对 | 贵、慢，但细 |

面试时可以说："我先用关键词做快速回归，再用 LLM-as-judge 做细粒度质检。"

## 面试怎么说

> "关键词匹配只能测出'关键数字有没有出现'，测不出答非所问和编造。所以我加了一层 LLM-as-judge：用模型按 faithfulness 和 relevance 两个维度各打 1-5 分。faithfulness 专门抓'资料里没有但模型自己补了'的情况。代价是每题多一次调用，所以只在离线质检跑，不进 CI。"

## 注意

- 裁判也是模型，**会犯错**，分数是参考不是真理；
- 想更稳，可以"两个裁判取平均"或"换一个不同厂商的模型当裁判"（避免同源偏差）。
