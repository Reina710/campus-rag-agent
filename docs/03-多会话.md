# 多会话（对话历史列表）

## 一句话

**同一个浏览器可以有多段互不干扰的对话，左侧抽屉里能切换、新建、删除。**

## 为什么需要

之前是"一个浏览器 = 一段对话"：清空就全没了，也没法同时开两个话题。主流产品都有侧边栏的对话列表，这是很基础的产品能力。

## 怎么做的

### 两把钥匙

- **sid**（浏览器）：存在 cookie 里，标识"这台浏览器"
- **conv**（对话）：前端生成，标识"这段对话"

记忆文件按 `data/memory/<sid>__<conv>.json` 存。所以：

```
浏览器 A ─┬─ 对话 c1  →  data/memory/A__c1.json
          └─ 对话 c2  →  data/memory/A__c2.json

浏览器 B ──── 对话 c1  →  data/memory/B__c1.json   ← 和 A 同 id 也不冲突
```

### 请求怎么带 conv

前端每个请求都带 `conv_id`：

```json
{"question": "奖学金多少钱", "conv_id": "cabc123"}
```

后端 `_conv()` 取出来、清洗（只留字母数字下划线短横），再拼成记忆 key。

## 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/conversations` | 列出当前浏览器的所有对话（标题取第一句提问） |
| POST | `/api/conversations` | 创建一个新对话 id |
| GET | `/api/conversations/<id>/messages` | 读回某段对话的历史（切换时恢复界面） |
| DELETE | `/api/conversations/<id>` | 删除某段对话 |

## 代码在哪

| 文件 | 作用 |
|---|---|
| `src/memory.py` | `list_conversations(sid)` 扫描记忆文件、按 `sid__` 前缀过滤 |
| `src/sessions.py` | `get(sid, conv)` / `drop(sid, conv)` 按复合 key 管理 agent |
| `web_demo.py` | `_conv()` 解析、`/api/conversations` 接口、`/ask_stream` 带 conv |
| `frontend/src/App.jsx` | `ConvsPanel` 抽屉、`switchConv` / `newConv` |

## 怎么验证

1. 起服务，页头点「对话」→ 点「+ 新对话」
2. 问一个问题 → 对话列表里出现一条（标题=你的问题）
3. 再点「+ 新对话」，问另一个问题 → 列表里两条
4. 点回第一条 → 之前的问答历史被恢复
5. 点某条的「删除」→ 消失

## 一个设计细节

**新对话的 id 是前端生成的**（`c` + 时间戳），不调后端。所以"新建"是瞬时的，第一句话发出后才会出现在列表里。这和 ChatGPT 的行为一致：空对话不占列表。

## 面试怎么说

> "会话是两层：cookie 里的浏览器 id，和前端生成的对话 id。记忆按 `sid__conv` 落盘，所以同一个浏览器可以有多段对话，互不覆盖。切换对话时会从记忆文件读回历史，前端恢复界面。单进程内存 + 文件持久化，要横向扩容就把会话挪到 Redis。"

## 注意

- 对话列表按**浏览器**隔离，换个浏览器 / 无痕窗口就看不到了；
- 清除浏览器 cookie 等于换了一个访客，旧对话还在磁盘上，但列表里不再显示（属于预期行为）。
