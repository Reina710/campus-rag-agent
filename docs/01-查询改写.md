# 查询改写（Query Rewriting）+ 指代消解

## 一句话

**用户问的话往往不适合直接检索。查询改写就是先用模型把问题"翻译"成 2-3 个检索友好的版本，再去搜。**

## 为什么需要

用户的话不是为检索写的：

| 用户原话 | 问题 | 直接搜的结果 |
|---|---|---|
| "奖学金咋评的？" | 口语，没有"评选标准"这个词 | 字面检索可能搜不到 |
| "它什么时候截止？" | "它"指谁？检索器不知道 | 完全搜不到 |
| "找实习" | 太宽 | 只能碰运气 |

**直接拿原话检索，命中率取决于"用户措辞刚好和知识库一致"这个巧合。**

## 怎么做的

一次模型调用同时做两件事：

1. **指代消解**：把"它/这个/那个"换成上一轮的真实主语
2. **多查询**：生成 2-3 个不同措辞的检索版本

然后**每个版本各召回一次，按块 id 合并、保留最高分，再取 Top-K**。

### 举两个真实例子（跑出来的）

```
原问题：它什么时候开放？
改写：  ['它什么时候开放？', '北京交通大学 选课系统 开放时间', '北京交通大学 教务系统 选课 什么时候开放']

原问题：奖学金咋评的？
改写：  ['奖学金咋评的？', '北京交通大学奖学金评定办法', '北京交通大学奖学金评审条件']
```

第一个例子里，"它"被上一轮对话里的"选课系统"替换了——这就是**指代消解**。

## 代码在哪

| 文件 | 作用 |
|---|---|
| `src/query_rewrite.py` | 改写模块本体（`rewrite()` 函数） |
| `src/kb_tools.py` | `search_knowledge` 调它，并把多路结果合并 |
| `src/agent.py` | 每次调工具前 `kb_tools.set_history(self.messages)`，把对话历史传下去 |
| `src/config.py` | `QUERY_REWRITE` 开关、`QUERY_REWRITE_MAX` 上限 |

## 怎么验证

```bash
# 单测改写效果（会真的调一次模型）
python src/query_rewrite.py

# 或者看完整链路：问"它什么时候开放？"，看返回的块里有没有"选课时间"
```

## 代价（面试要主动说）

- **每题多一次模型调用**：延迟 +1~2 秒，成本略增；
- **改写可能跑偏**：所以最终回答仍用**原问题**，不用改写后的版本；
- **保底**：改写失败/超时，自动退回原问题，主流程不受影响。

## 面试怎么说

> "用户问法和知识库措辞经常对不上，尤其口语和指代。所以我在检索工具里加了一层查询改写：先让模型把问题改写成 2-3 个检索友好的版本，分别召回再按块合并。指代消解也在这一步做——'它什么时候截止'会被替换成上一轮的主语。代价是每题多一次模型调用，所以做了保底：改写失败就退回原问题。"
