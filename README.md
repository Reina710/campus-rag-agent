# Campus Knowledge-base QA Agent

> 一个面向校园知识库的问答 Agent：ReAct 循环 + 可插拔检索器 + 系统化评测。
> 不依赖任何 Agent 框架，各层均有可复现的量化评测结果。

## 项目定位

多数 RAG 项目的结论停留在"接了框架，效果不错"。本项目的重点是把这句话拆开，逐层量化：

- 检索质量：四种检索器在同一题库上对比，评测命中率、recall@K、MRR
- 检索短板：用 recall@K 量化答案跨块时的召回缺失，`0/2 → 1/2 → 2/2`
- 端到端断层：检索命中率 96.6%，回答通过率 93.1%——定位到 Top-K 上下文容量问题

## 架构

```
用户提问
   ↓
Agent 主循环（ReAct，模型自主决定是否检索、是否换词重查）
   ↓
检索（封装为工具 search_knowledge，可插拔）
   ├─ freq   字频（基线）
   ├─ bm25   分词 + IDF
   ├─ embed  向量（阿里云 text-embedding-v3，索引落盘）
   └─ rrf    bm25 + embed 融合
   ↓
上下文拼装（Top-K 块 + 防注入隔离 <untrusted_data>）
   ↓
生成（DeepSeek，仅依据检索到的资料回答，缺失则明确说明）```

关键设计：检索以工具形式接入，由模型自主决定调用时机与次数，区别于固定的"检索 → 拼 prompt → 生成"流水线。

## 评测数据

### 检索层：四种检索器对比

| 检索器 | Top-1 命中 | Top-K 命中 | recall@3 | MRR |
|---|---|---|---|---|
| freq | 81.5% | 92.6% | 0.926 | 0.864 |
| bm25 | 88.9% | 100% | 0.982 | 0.944 |
| **embed** | **96.3%** | **100%** | **1.000** | **0.982** |
| rrf | 92.6% | 100% | 1.000 | 0.963 |

### 结论

1. **recall@K 量化跨块短板。** 对答案分散在两块的题目：freq 召回 0/2、bm25 1/2、embed 2/2。字面检索难以召回"语义相关但字面不重复"的块，recall@K 能够暴露这一缺失。
2. **MRR 反映排序质量。** embed 的 MRR 0.982，正确块几乎始终排第一；freq 仅 0.864，命中后常排在第二三位。
3. **单路足够强时，融合不占优。** embed 已达 100% Top-K 命中、recall 1.0，RRF 无提升空间，Top-1 反而下降（92.6% < 96.3%），原因是引入了 bm25 的字面噪声。

### 端到端：检索提升未转化为回答质量

| 检索器 | 检索命中率 | 回答通过率 |
|---|---|---|
| freq | 93.1% | 93.1% |
| embed | 96.6% | 93.1% |

embed 检索命中率更高（多召回一道跨块题），但回答通过率相同：跨块题的答案分散在多个块中，Top-K=3 的上下文容量不足以完整承载，模型仍拿不到完整信息。

**改进方向**：增大 Top-K、多路融合或重排（rerank）。

### 切块参数对照

| 切块方式 | 块数 | 命中率 | 标志词召回率 |
|---|---|---|---|
| heading 按标题 | 38 | 100% | 79.1% |
| fixed 300 字 | 19 | 100% | 81.7% |
| fixed 500 字 | 11 | 100% | 81.7% |
| fixed 800 字 | 7 | 100% | 81.7% |

在当前知识库规模（约 7000 字）下，切块字数对召回率不敏感。采用 heading 切块是因为校园知识天然"一个标题一个知识点"，语义边界更清晰。

## 工程记录

1. **字频检索的误召回**：查询"什么是 RAG"时 Top-1 召回"ReAct 循环"（字符重叠所致），由 Top-K 兜底。说明 Top-K 是对检索误差的余量设计，代价是引入无关上下文。
2. **注入攻击评测需构造有效样本**：转账/忽略规则类指令对 DeepSeek 无效；使用"伪装教务处修改选课时间"类事实篡改样本才得到稳定差异：未加固版本受骗，加固版本（`<untrusted_data>` 信封隔离）守住。
3. **上下文压缩会丢失关键事实并引发幻觉**：删除"研二专硕找算法实习"后，模型生成错误推断。上下文压缩的目标是保证关键事实不被幻觉覆盖，而非仅节省空间。
4. **tool_call_id 无法跨会话持久化**：将 tool 中间产物持久化到文件后，重启导致引用失效。持久化仅保存干净的问答对。
5. **向量检索开销优化**：缓存、批量请求、索引落盘三层优化，冷启动请求数从 37 次降至 2 次。

## 快速开始

### 方式一：Web Demo

```bash
pip install flask
python web_demo.py               # 或运行 run_web.bat
```

浏览器打开 `http://127.0.0.1:8000`。页面展示答案及本轮检索命中的知识块（含相关度），顶部为四项核心评测数字。

### 方式二：命令行

```bash
pip install -r requirements.txt   # 依赖 openai + jieba
cp .env.example .env              # 配置 DEEPSEEK_KEY 与 DASHSCOPE_KEY
```

```bash
运行 run.bat        # 对话（/hits 查看检索命中，/history /clear）
运行 run_eval.bat   # 运行评测，结果写入 reports/
```

评测数据已保存在 `reports/`，审读代码与结论无需配置密钥。

## 技术栈

Python 3.11+ · DeepSeek · 阿里云 text-embedding-v3 · jieba

不依赖 Agent 框架：ReAct 循环、检索器、上下文拼装、评测均为自行实现。
